Task completion no longer loops on the evidence gate. Completing a todo now accepts the latest verification result automatically: when `todowrite` receives `status: "completed"` without `evidence`, or with a callID that is unknown or reused, the newest successful tool result after the request (preferring an edit or a shell check) is recorded as the evidence and the tool output says which one. Verification commands (`bash`, `shell`) no longer invalidate earlier evidence; only a later edit to the verified files does, and an edit still streaming in the same assistant message as the `todowrite` is no longer held against it. Refusals are now distinct and actionable (no result since the request, unknown callID, reused callID, evidence older than the request, evidence before a later edit) and list the recent callIDs, tools and messageIDs inline. Updates may address a task by `id` and `revision` alone (`content` and `priority` stay as stored), `text`, `title` and `task` are accepted as spellings of `content`, and a malformed update quotes the missing keys with a minimal correct example. After two refused completion attempts for one task in a turn the task is blocked with that reason instead of prompting a third try; the loop guard counts repeated identical failures even when the arguments drift and no longer restarts at synthetic todo continuations. The TUI folds consecutive failed `todowrite` calls into one "Todo update failed ×N" row that expands to the last message, and the todowrite, design and continuation instructions describe the real protocol.
