Design audits list what matters first on a noisy page: a check found at several widths becomes one line ("390/768/1440px"), errors come before review and info, the repetition and reuse findings lead their severity instead of falling past the 30-line cap, and the report says how many checks were merged and how many more are in the full report. The reuse check is linear and bounded (200 source files, 256 KB each, 4 MB in all, with an info line when a bound left files out), and a failing reuse check becomes an info line instead of failing the audit. It no longer calls a capitalized constant a re-declared component, a local `./card` import a design-system import, or every color off-token when the design system only declares a radius; colors compare with alpha stripped across hex, rgb, hsl and oklch, so `hsl(220 14% 96%)` matches a shadcn `--muted` token, and native `<button>` or `<input>` elements are noted (info) when the design system has a Button or Input. Layout signatures are taken once at the widest audited viewport and kept with their width, two different layouts made of plain boxes are no longer called alike, and text width counts East Asian characters as two columns so a translated clone is still recognised. The System One judge no longer asks about accepted exceptions, reuses its verdict while an item is unchanged, sends nothing in observe mode, and sends component, prop and import names instead of source lines. An accepted exception applies to the next audit without a new revision. Jobs written by a newer version with an unknown check severity still load (read as review). The approved-signature file is written one approval at a time, an unreadable or newer file is kept instead of overwritten, and write failures are logged.
