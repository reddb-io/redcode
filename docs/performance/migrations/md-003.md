# MD-003 — projeção incremental de Markdown

- Estado: `REJECTED`
- Plataforma: Windows x64, Bun 1.4.4, Ryzen 5 3600
- Jornada: resposta do assistente em streaming no web app e desktop
- Processo: Web Worker da UI; parsing/highlight não roda no renderer principal
- Artefatos: `md-003-baseline.json` e `md-003-tail-incremental.json`

## Evidência e decisão

A hipótese de custo era válida, mas não exigia Rust. O pipeline já executava
Marked, remend e Shiki em Worker e já tinha um fast path incremental para code
fences abertos. Prosa crescente, porém, reprocessava o documento inteiro a cada
delta.

Com 100 KB recebidos em 391 deltas de 256 bytes, o baseline de prosa acumulou
4.925,36 ms, com pior passo de 27,35 ms e 18,82 MiB de RSS incremental. A projeção
da cauda instável em TypeScript reduziu a coleta final para 35,95 ms, pior passo de
1,21 ms e 9,09 MiB: aproximadamente 99,3% menos tempo total e 51,7% menos RSS.

A implementação conserva blocos congelados por identidade, reprocessa somente a
cauda cujo texto-fonte ainda é exato e volta ao documento completo para referências
Markdown, replacements ou caudas normalizadas pelo parser. Um teste diferencial
com deltas de 1, 3, 17 e 64 caracteres compara cada projeção incremental com o
parse completo; 32 testes/289 asserts passaram. O teste também encontrou e corrigiu
um bug preexistente em language metadata de code fence repartida entre deltas.

Rust foi rejeitado porque a melhoria algorítmica supera o orçamento sem trocar o
parser nem criar fronteira WASM/FFI no frontend. Reabrir somente se profiling real
atribuir custo material ao parser da cauda, Shiki ou reconciliação DOM depois dessa
mudança.

## Validação adicional em 13/11/2026

Uma comparação diferencial encontrou um caso em que uma fórmula com delimitadores
`$` ou `$$` e linhas em branco podia alterar blocos já considerados estáveis.
O caminho incremental agora retorna ao parse completo quando encontra uma possível
abertura de fórmula em bloco. Testes cobrem deltas de tamanhos variados, referências,
blocos de código e fórmulas. Uma verificação adicional de 867 combinações e tamanhos
de delta não encontrou divergências.

No ensaio sintético de 100.000 caracteres de prosa em 391 deltas, a projeção
incremental levou 72,8 ms contra 4.086,9 ms ao reprojetar o documento completo.
Essa é uma comparação local de projeção, não uma medição de ponta a ponta no
Electron. Os números de RSS do ensaio usam o mesmo processo e não demonstram
redução de memória; não são suficientes para estimar economia de RAM ou CPU total.

Passaram 37 testes de Markdown/cache, o teste de streaming no Chromium, as
checagens de tipos e o `bun run check` geral. A suíte completa de session-ui teve
311 testes aprovados e uma falha ao carregar `markdown-solid.test.tsx`: o runtime
Solid não exportou `jsxDEV`, antes da execução dos testes daquele arquivo.
